## Allowed classifications

### KEEP

Default conservative classification. A test remains executable evidence unless exact file:line evidence shows that its assertion is tied to superseded constitutional authority or is no longer meaningful under the active architecture.

Reason used by M0-A:

> Preserve executable behavioral evidence until a later milestone supplies file:line evidence for rewrite or retirement.

This category includes runtime behavior, deterministic behavior, safety boundaries, persistence behavior, mutation behavior, model/vector no-load defaults, AGP/fallback gates, and regression tests. `KEEP` does not mean the implementation is endorsed by EVE v4; it means the evidence must remain available during M0.

### REWRITE

Applied when a test source directly references one of these superseded authority documents:

- `docs/EVE_DESIGN_v3.md`
- `docs/EVE_DESIGN_v3_1.md`
- `docs/EVE_IMPLEMENTATION_STATUS_v3_1.md`
- `docs/EVE_DEPENDENCY_MAP_v3_1.md`

The generated entry records the first exact matching line. The future rewrite must point to active v4 authority while preserving the behavioral or historical assertion. M0-A only classifies; it does not perform the rewrite.

### RETIRE

No test is retired by the M0-A default policy. Retirement requires specific file:line evidence that the test has no remaining behavioral, migration, historical, safety, or regression value. That determination is deferred to the relevant later milestone.

## Required fields per test file

Every generated test classification contains:

- repository-relative path;
- exact evidence line;
- `manual_classification` of `KEEP`, `REWRITE`, or `RETIRE`;
- classification reason;
- detector and mechanical evidence;
- confidence;
- unresolved status;
- manual-only status.

## Manual policy decision

The committed M0-A policy is intentionally asymmetric:

1. retain tests by default;
2. classify exact superseded-authority references as `REWRITE`;
3. classify nothing as `RETIRE` without additional evidence;
4. leave implementation behavior unchanged;
5. treat test count as inventory, not as a quality claim.

This prevents M0-A from laundering architectural changes through test deletion or broad reclassification.

## Follow-on ownership

- M0-B may identify tests requiring rewrite for gates, bypasses, exception swallowing, clocks, queues, threads, concurrency, or nondeterminism.
- M0-C may identify tests requiring rewrite for persistence, memory, self-model, relationships, affect, hormones, goals, checkpoints, vectors, and operator artifacts.
- M0-D may recommend final module and test disposition after neural, vector, adaptive, and life-loop evidence is integrated.

Until those reviews supply exact evidence, M0-A's conservative `KEEP` classification remains in force.
